# Architecture Decision Records


## ADR-005: 사용자 저니와 실험 흐름을 구분한 상세 초안 (2026-10-08)

사용자가 구현 전 구체적인 계획과 사용자 저니·User Flow를 요청했다. 기존 원문은 보존하고 `docs/PRODUCT_PLAN.md`에 대상 사용자 가설, 정상·예외 흐름, 화면 제안, 계약과 단계별 완료 조건을 기록한다. 질문→설명→인용→원문 대조를 사용자 목표로 두고 데이터 적재·검색 평가는 개발팀 흐름으로 구분한다. 화면 추가는 기존 API·실험 MVP의 확정 범위로 간주하지 않는다. 하네스 구현 단계는 pending 초안으로 등록하고 제품 구현·커밋·푸시는 실행하지 않는다.

## ADR-001: Codex 전용 하네스 (2026-10-08)

사용자 요청에 따라 개발 에이전트는 Codex만 사용한다. 원본 harness-framework의 단계 파일, AC 게이트, 제한된 상태 필드, 재시도·재개를 유지하고 Claude 명령은 `.agents/skills/`, 호출은 `codex exec`로 바꾼다. Claude 훅은 설치하지 않는다. TDD는 작업 지침으로 유지하며 AC와 보호 파일 검사는 실행기가 수행한다. 원본의 도구 호출 훅과 동일한 강제를 제공한다고 주장하지 않는다.

## ADR-002: 실제 Git 루트에 적용

`docker-qdrant/`는 저장소 일부다. Python 모듈과 Notebook까지 공통 지침을 적용하도록 하네스는 `rag_mini_pj/` 루트에 둔다. 기존 협업 계획은 이동하거나 덮어쓰지 않는다.

## ADR-003: 기존 스택과 초안 유지

uv/Python/FastAPI/Qdrant/LangChain OpenAI 호환 클라이언트를 유지한다. Codex 선택은 앱의 MonoRouter 교체를 의미하지 않는다. 기존 기획의 미정 사항은 초안에 남기고 실제 구현·검증으로만 완료 판정한다.

## ADR-004: 자동 커밋을 명시적 옵션으로 변경

사용자 변경이 존재하므로 원본의 기본 git add -A/자동 커밋은 선택 기능으로 바꾼다. 기본 실행은 현재 브랜치에 변경을 남긴다. `--commit`은 깨끗한 작업 트리에서 기능 브랜치와 검증 후 커밋을 만든다. `--push`는 커밋을 포함한다. 더러운 작업 트리에서 자동 커밋 재개도 거부하므로 실패 작업은 기본 모드로 재개하거나 먼저 수동 검토·커밋한다.
