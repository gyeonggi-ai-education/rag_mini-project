# PRD: AI 기본법 근거 기반 QA

## 기획 상태

- 단계: 사용자 저니 중심 상세 기획 (초안, 2026-10-08)
- 상세 제안: [사용자 저니와 구현 계획](PRODUCT_PLAN.md). 기존 MVP와 화면 확장 제안을 구분한다.
- 원문: [협업 계획](../docker-qdrant/docs/project-plan.md). 사용자 지시와 합의가 새 문서보다 우선한다.
- 열린 질문: 입력 PDF 위치·버전, 모델/임베딩 ID와 MonoRouter 지원, chunk/search 계약의 최종 합의, 컬렉션 이름·차원, 팀 통합 범위.

## 목표와 사용자

AI 기본법 PDF를 바탕으로 질문에 답하고 실제 조문·항·페이지 출처를 반환한다. 학습 팀은 같은 데이터와 Golden Set으로 Dense, Rerank, Multi Query 검색을 비교한다. 기존 초안은 3~4시간 협업을 전제로 하며 본인은 데이터·청킹을 담당한다.

## 유저 플로우와 핵심 기능

일반 사용자 흐름은 질문 작성 → 설명 확인 → 주장별 인용 확인 → 원문 대조 → 조건을 보완해 다시 질문하기다. 첫 버전은 API/Notebook으로 검증하며 웹 화면은 확장 제안이다.

개발팀 흐름은 PDF 원문·버전 확인 → 구조 보존 청킹 → 임베딩과 Qdrant 적재 → 원질문 검색 → 근거 기반 답변·출처 → 동일 평가셋 비교다.
목표 API는 POST `/ask`, 입력은 질문과 검색 모드, 출력은 답변과 실제 사용한 근거다. 빈 질문, 검색 결과 없음, 모델 호출 실패를 처리한다. 근거가 부족하면 문서에서 확인하기 어렵다고 답한다.

Dense를 기준선으로 먼저 연결하고 Rerank와 Multi Query를 비교한다. Multi Query는 원질문 포함·확장 수 제한·chunk_id 중복 제거를 지킨다. 초기 평가셋은 답변 가능 8문항과 불가 2문항이며 결과와 실패 사례를 기록한다. 후보 20, 최종 K=5, 확장 최대 3은 원문 초안의 제안이며 확정값이 아니다.

## 구현 상태와 완료 기준

현재 환경·모델·Qdrant 클라이언트 공유 모듈과 실험 Notebook, Compose가 있다. 2026-10-08 파일 확인 기준 `app/main.py`에는 FastAPI 앱과 GET `/` 응답이 있다. `/ask`는 없으며 전체 PDF 청킹·적재, 평가 실행기는 완료 증거가 없다. 실제 조문 검증, 전체 적재, 출처 포함 API, 동일 평가셋 결과와 재현 절차가 있어야 MVP 완료다. 하네스 설치는 제품 완료와 별도다.

## MVP 제외 사항

별도 프런트엔드, 인증·결제, BM25/Hybrid, 배포, 대규모 파라미터 탐색은 현재 범위에 없다. 결합 검색은 시간이 남을 때 검토한다.
